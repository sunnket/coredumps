The drill measures correctness. It never measures time.

Every drill record stores which Leitner box a line is in, how many times it was right, and when it is next due. There is no timing anywhere — so the app can tell someone “you can type this correctly” but never “you can type this fluently.”

Those are different skills, and the second is what makes a person look competent in a live coding round. Adding elapsed time and a personal best per card converts the existing bank into a fluency trainer without writing a single new card.

record() stores → box, ok, miss, seen, due
never stores → duration, wpm, best

Each rung is a

Fragment → line → block → from memory, against the clock

The escalation you described maps onto four genuine stages. The jump that matters is rung 3 to 4: producing a block without the target on screen is the skill an interview actually tests.

01fragmentType if, def, for x in — repeated until the shape is automatic
02lineOne full statement, visible, timed. Beat your own previous time
03blockThree to six lines with correct indentation, still visible
04from memoryTarget hidden. Only the intent is shown. This is the one that counts

Rung 4 already exists — the drill's recall phase does exactly this. It just is not timed, and there is no ladder connecting the rungs.

There is no JavaScript track

HTML has 7 lessons, CSS has 9, and the guided route has a whole web stage. But there is no JS — so a learner can style a page and cannot make it do anything. The stage dead-ends.

This hurts the AI path too. Every AI product has a frontend, and most AI-engineer postings list JavaScript or TypeScript. It is also the natural home for a React track later.

Structural

Nothing in a lesson actually runs

The 117 katas are checked by comparing typed characters against a reference solution — nothing is executed in the browser. Lessons have no runnable cell at all.

So a complete beginner reads Python prose for hours before running a single line. The read-to-do gap is where most self-taught learners quit. An in-browser Python runtime on lesson code blocks would close it.

Projects are a library, not a portfolio path

The projects are genuinely excellent — real problems, real stacks, real pitfalls. But nothing says “finish these three, in this order, and you have a portfolio that gets interviews.”

A beginner facing 60 options picks badly or picks nothing. Three named capstones per track, sequenced and gated, converts a library into an outcome.

No timed mock interview

The interview bank is a browsable reference with self-assessment. There is no round: 45 minutes, three questions, no peeking, a verdict at the end.

Reading answers builds recognition. Performing under a clock builds the thing being hired for — and it is the single cheapest way to make someone feel company-ready, because it tells them honestly whether they are.

The honest summary: you do not have a content problem. 382 lessons and 1,240 terms is more than most paid platforms ship, and the writing quality is consistently high.

What you have is a practice-and-proof problem. The path teaches well and then stops short of making someone perform — no clock, no runnable code, no sequenced portfolio, no mock round. Items 1, 3, 4 and 5 above are all about that one gap, and together they are less work than the JavaScript track alone.
